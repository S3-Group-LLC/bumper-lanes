# Glossary

Plain-English meanings of words you'll hear while building. Your agent adds new
words here when it explains something (the `explain-that` skill).

- **Agent** — an AI that can take actions (edit files, run checks), not just chat.
- **AGENTS.md** — the rulebook your agent reads at the start of every session.
- **API** — a service's "front door" for programs: send a request, get a reply.
- **Backup** — a saved copy of your code, site or data that you can go back to.
- **Branch** — a private copy of the project where changes are tried out without touching the live site.
- **Build** — turning your project's code into a website that can be put online.
- **CHANGELOG.md** — a plain-English diary of every change to your project.
- **Command line (CLI)** — typing commands to run programs; your agent does this for you.
- **Commit** — a saved snapshot of changes, with a note saying what changed.
- **Context window** — how much an agent can hold in mind at once.
- **Database** — where your app keeps information between visits; yours is Supabase.
- **Deployment** — one version of your website put online by Vercel.
- **Environment variable** — a named setting (like a database address) kept outside the code. Secret ones live in Vercel or GitHub settings, never in the code.
- **Lint** — an automatic check that code follows the agreed rules.
- **Live site** — the real website everyone sees (your `main` branch).
- **MCP** — a standard plug that gives an agent ready-made tools for a service.
- **Merge** — accepting a pull request. In this project, merging publishes your change to the live site.
- **Migration** — a small file describing one change to the database, applied in order so changes are tracked and repeatable.
- **Preview** — a private test copy of your website for one pull request.
- **Publishable key** — the Supabase key that's safe to use in a browser; Row Level Security decides what it can see.
- **Pull request (PR)** — a request to bring a branch's changes into the live site. It shows what changed and gives you a preview link.
- **Repository (repo)** — the folder that holds your whole project and its history, stored on GitHub.
- **Restore** — putting data back from a backup.
- **Row Level Security (RLS)** — database rules that decide who may read or change each row of data.
- **Secret** — a password or key that must never be in your files or a chat; it lives in a vault (Vercel or GitHub settings).
- **Skill** — a saved, step-by-step playbook your agent opens when a task needs it.
- **Template** — a ready-made project you copy and make your own.
- **Test** — a small program that checks one thing works; tests are your agent's eyes.
